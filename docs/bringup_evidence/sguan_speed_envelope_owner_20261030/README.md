# 转速包络、控制权和 SMP 等锁窗口实板验证（2026-10-30）

## 结论与当前使用

用户确认 24 V 电源直流侧限流 2.5 A、电机已固定且空载后，分阶段扩展当前直接反馈 SMO。
正常固件最终保留 CAN 桥和精简六字段状态，已烧录，最后为 **CAN owner、空闲、GPIO23 低**。

| 项目 | 最终范围/结果 |
| --- | --- |
| 启动目标 | 350～800 rpm（绝对值），建议先正转 500 rpm |
| 闭环后同向改速 | 350～2500 rpm（绝对值）；本轮实板只测正转 |
| 3000 rpm | 未通过，估速约 2820 rpm 时捕获 21.63 V 母线读数并关断 |
| 300 / 250 rpm | 未通过原速度误差判据；未继续上板测 200 / 150 rpm |
| 电流 | 未提高：相电流软件门限 3 A，速度 PI 的 Iq 上限仍为 0.9 A |
| 供电 | 用户设置的 2.5 A 是直流侧限制，不是相电流峰值，也未独立测量直流电流 |

```text
motor owner                 # 上电默认 can
motor owner uart
motor owner                 # switching 时继续查询，直到 uart
motor closed 500 0.8
motor status                # 等待 state=closed
motor speed 2500
motor stop
motor owner can
```

切换控制权总是先发 STOP，确认控制核关断后才授予；不自动启动，也不清除锁存故障。
非 owner 的 START/SPEED/RESET 被拒绝，串口紧急 STOP 始终可用。
UART owner 下 CAN 不发送电机命令，包括因 NMT reset 抢停；切回 CAN 后旧 0x000F 不能直接重新启动。
上述规则不提供核心死锁时的独立硬件急停保证，人员仍须可切断驱动电源。

## 最终保留的控制改动

- 继续使用修正后的硬 sign SMO、原版 I/F、PI/PLL/math，不加入边界层或弱磁。
- 电压矢量限幅由 `min(6 V,.35×VBUS)` 改为 `min(11.5 V,.43×VBUS)`，Q 轴 PI 输出和积分上限改为 ±11.5 V。
  D 轴上限、PI/PLL 增益、电机参数、20 kHz 周期不变。
- h 在参考速度 800 rpm 以下为 6，800～2000 rpm 线性增加至 12，以上为 12。
  低速不直接套用固定 12 V 注入，调度仅改变原有 h 参数，不生成角度或电流给定。
- 启用上游现有角度补偿：Td=1.1 ms、固定偏置为 0。这是测试范围内对 SMO 低通滞后的近似补偿，
  不是独立测得的电机角度，也不是对任意频率的精确补偿。
- PWM 限制仍为 0.1～0.9，1 µs 死区及 ADC 采样窗口未缩短。
- 早期低速参数及低速保持状态试验均已撤回，最终 I/F 接管和板级监督与开始时相同：
  观测器在机械参考 25 rad/s 开始计算，35 rad/s 以上接管。
- `foc_limits.h` 统一 UART/CAN/CPU0 范围：启动 350～800、改速 350～2500、估算超速 2750 rpm、
  相电流 3 A、母线 22～27 V。相电流正负值、非有限值、母线和估算超速在 ADC ISR 关断并锁存。

3000 rpm 是资料中的额定目标，不是已确认的最高安全轴速。没有验证额定 6.6 A、额定转矩或功率。
早先转载资料的峰值扭矩数据存在量纲/一致性疑问，本次未据此扩大电流。

## 上探与下探：保留失败记录

所有有效速度段保持 8 s，最后 3 s 的串口样本最大估算误差不超过 50 rpm、平均不超过 25 rpm。
诊断 ISR 在相电流达到 3 A、母线不在 22～27 V、ISR 达到 50 µs、任一次 ADC overflow 或运行总期限
到达 60 s 时关断。正式固件保留原来的连续 3 次 overflow 关断策略；诊断验收更严格，不跳过单次事件。

- `high-1000-valid`：500→800→1000 rpm，通过。
- `high-3000`：500→1000→1500→2000→2500 均通过；向 3000 升速过程中被母线 21.632 V 读数关断。
  该轮用户没看清电源是否进 CC，因此不能确定是供电掉压还是采样尖峰；没有降低停机阈值重试。
- `low-150`：500、350 rpm 通过；250 rpm 最大误差 68、平均 35.27 rpm，主机拒绝并停机。
- `low-300`：300 rpm 最大误差 77、平均 35.36 rpm，拒绝并停机。
- `final-envelope`：撤掉低速试验后，500→350→800→1500→2000→2500 全部通过；
  350 rpm 最大/平均误差 48/23.91，2500 rpm 为 5/3.91，电流采样峰值 1.326 A、ISR 峰值 28.81 µs。
  此时 CAN 电机桥在隔离版中临时断开，不能当作新 owner/CAN 常驻的最终验收。
- 最初 `high-1000` 在启动前发现一条诊断输出超过控制台行缓冲而被截断，未启动电机；
  拆短输出行后才继续，原始含 NUL 日志保留，不作为有效运行。

模型覆盖了标称磁链 .0152 Wb，以及 .021 Wb 的电压余量不足案例。某些低速提前接管和高转速直接冷启动
候选未通过模型，没有把这些失败当作实板成功，也没有保留试验性低速控制逻辑。
最终高转速从已建立的 500 rpm 闭环改速，不承诺直接 `closed 2500`；该命令在入口被拒绝。

## Owner 实现与 SMP 时序问题

`control_owner/owner_pending/owner_stop_seq` 只属于通信核；没有扩大六字段状态结构。
授予 owner 前验证 STOP 邮箱已确认、状态快照可读且为 Idle/Fault、确认序号覆盖本次 STOP。
主机回归覆盖切换期间拒绝两个来源、取消待执行 START、快照忙、序号回绕、故障保留及旧 CAN enable 不重放。

保留 CAN 常驻后，`owner-envelope` 在 2000 rpm、同镜像 `owner-envelope-repeat` 在 1500 rpm 出现单次 overflow，
均停机并保留故障。没有将失败轮的停止清理或 owner 返回当成通过。

`irq-probe` 仅增加隔离计时，测到：

- 事件前 CPU0 `rt_sched_lock()` 外层连续屏蔽约 57.03 µs；后续观测最大约 58.32 µs。
- ADC ISR 入口间隔最大 97.01 µs，而 ISR 本体峰值约 30.32 µs。
- 保存的调用地址 `0x08021061` 由该轮 ELF 解码至 `rt_sched_lock`，`scheduler_mp.c:571`。

因此有足以跨过 50 µs 周期的关中断路径，不能只调 SMO 参数。用户明确授权后，有限修复 BSP：

1. CPU0 初始化 ADC 时登记唯一的优先级 0、无 RTOS 调用 ISR；检查 IRQ 身份、使能、优先级分组及
   其他已启用外设没有优先级 0，否则拒绝登记并保持功率级关闭。
2. 只在软件锁忙等及未取得 SEMA 的退避区临时用 BASEPRI 屏蔽优先级 1～15，开放优先级 0 ADC。
3. 不在这些窗口持有本地锁/SEMA，不写内核数据，不调用 RTOS。重试获取锁之前恢复原 PRIMASK/BASEPRI。
4. 持锁区域、普通关中断区域、CPU1 不变；不是把全局关中断改成可抢占，也没改调度器源码。

优先级 0 从此专用于这个不调用 RTOS 的 ISR；后续增加外设或修改 ADC 回调时必须保持约定。
主机模型测试实际头文件和锁函数，验证原屏蔽位恢复、其他优先级仍屏蔽、SEMA 与软件锁等待、CPU1 不变。

修复后的诊断日志保留了原字段名 `irqoff_*`，但此时它们包含开放 ADC 的等待窗口，
**只能解释为外层临界区耗时，不能再当作连续屏蔽 ADC 的时间**。
入口间隔仍存在变化，不能宣称完全消除延迟或获得严格 WCET。

## 保留 CAN 常驻的最终实板重复验证

两轮都使用同一镜像，先验证上电 CAN owner 下串口 START 被拒绝，切到 UART 后才启动。
运行期间 CAN 线程/桥接均保留。结束时从运行状态请求 CAN owner，确认先关断；UART START 再次被拒绝。

日志中的 `estimated_dc_mA` 是软件功率近似，不是电源直流电流测量，不能据此证明没触及 CC。

## 最终正常镜像

正常主工程没有临时 DWT/峰值计数和诊断命令，保留 CAN owner 默认与新控制包络。
双 Bank 下载校验成功，随后只做不使能输出的检查：默认 CAN 拒绝 UART START、空闲交接至 UART、
拒绝 `closed 2500`、交回 CAN、STOP；再读 GPIO23 低、复位，确认默认 CAN 和空闲状态。
最终未在没有诊断数据的情况下绕过验收再运行电机。

完整通过/失败日志、精确固件/源码校验值见 `manifest.json`；主机回归输出见 `verification.json`。
`diagnostic/` 中的 runner 会烧写和启动硬件，不要为了查看数据执行它。
