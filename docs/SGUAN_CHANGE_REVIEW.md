# SguanFOC 本地改动审查

## 当前新增：SMO 直接反馈修正（2026-10-30）

用户审阅 diff 后授权实施及实板测试。`Sguan_SMO.c` 仅将硬 sign 注入移至积分前，
将电流预测器的滤波 EMF 反馈改为直接开关注入；EMF 输出低通保留且使用同一注入。
这是反馈与离散时序修正，不是改 PLL 或给速度显示增加滤波；没有加入边界层。
公开头文件、数学源码、PLL/电机/SMO 参数、IF 和当前精简状态接口均未更改。

500 rpm A→B→A→B 和 800 rpm A/B 的实板对照表明原始 PLL 标准差下降约 80～83%，
控制角高频输出纹波明显降低。修正版启动、500→600→500 改速及停机通过；
滤波速度与 Iq 没有一致改善，不将其表述为全部转速波动已解决。
记录见[直接反馈实板证据](bringup_evidence/sguan_smo_direct_feedback_20261030/README.md)。
一致性测试只允许这一精确 SMO 增量，新增模块回归验证积分前注入、两轴离散递推及
滤波输出不参与电流预测反馈；其他模型/状态/ADC/IPC/ARM 回归仍保留。

## 修复前基线：按用户要求最大复用后

此前“单独撤销失败”的结果受到不同修改耦合，不能证明整套改写都必需。
补充隔离试验发现，原版 SMO/IF/PLL 配合最小反向符号修正也能完成模型跟踪。
因此当前已恢复 `SguanFOC.h`、`Sguan_SMO.c/.h`、`Sguan_math.c/.h` 原样，
原版 IF/电流环/位置环、SMO sin/cos 相位检测、20 kHz PLL 也已恢复，不再保留
额外 IF 状态字段、边界层、`atan2f()` 检测器、2 kHz 降频和新的融合状态机。

除上游预留的 `UserData_*` 配置外，只有 `SguanFOC.c` 存在约 28 行增加、12 行删除：
字段名修正、SMO 反向误差符号、跳过不存在的绝对编码器、仅 SMO 模式的电压缩放/限幅，
以及少量 GCC 固定模式分派和 ITCM 入口标记。其他模式的原版路径保留。

闭环状态和有界保护现在属于 `applications/sguan/foc_sensorless.h` 的只读监督，
不生成电角度或电流给定，不伪造库的 `Sensorless_Flag`。超时和失跟踪由板级硬件关断。
`forced_mrad` 只是最后 IF 角度的诊断快照，不再据此证明原库的角度独立性。

当前 16 组方向/速度/初始角度模型、正反转堵转期限、稳态误差、原版一致性、
SMO/NLFO 编译、IPC 和独立 ARM 编译/链接均通过。初次收敛时因 CANopen 台架排除
电机模块而未上板；之后用户确认 CANopen 完成，已重新启用并通过 500→600→500 和
800→700→800 rpm 两轮实板限时回归，ISR 观测峰值分别为 27.185/27.470 µs，
电流采样峰值为 1.272/1.189 A，两轮 ADC overflow 均为 0。
记录及边界见 [实板证据](bringup_evidence/sguan_upstream_reuse_20261029/README.md)。
完整说明见 [适配记录](../applications/sguan/README.md)。

**下面保留的是此前实现及对照试验的历史过程，不代表当前仍保留这些修改。**
`tests/sguan_change_review.py` 已转为校验当前上游复用一致性和只读监督，不再重现旧状态机的撤销矩阵。

## 基点升级

子仓库 `libraries/SguanFOC_Library` 的 `ns800` 分支已从 `91f58d5` 快进到用户指定的：

```text
5680b9ebce89203df0790c5e2313e7fd812513e9
```

仍编译其中的 `SguanFOC库v3.1.0(无感foc，浮点运算，进阶)`，没有切换到 Q31。
旧基点只是为了匹配最初拷贝的源码，不是不能升级的技术限制。

两个提交间 v3.1.0 目录仅有两行上游变化：

- `SguanFOC.h`：`VBUS_MIM` 更名为 `VBUS_MIN`。
- `UserData_Motor.h`：示例参数同步使用 `VBUS_MIN`。

但最新上游 `SguanFOC.c` 仍有两处 `safe.VBUS_MIM`，直接编译会与新结构体不一致。
本地将两处引用同步为 `VBUS_MIN`；保留 ATK 的 12～30 V 参数，而不是覆盖为上游示例的 10～14 V。
其他版本目录（尤其 v3.1.1 Q31）保留该最新提交的原样，不移植本项目修改。

## 审查结论

“曾经改过”不等于“每处都必需”。本轮区分接口必需、当前参数下的功能修正、
性能优化和可选策略，不以一次正转仿真判断所有改动都必要。

| 改动 | 证据/性质 | 处理 |
| --- | --- | --- |
| `VBUS_MIN` 两处核心引用 | 最新结构体已更名，旧引用无法编译 | 必须修正 |
| `UserData_*` 板级参数、ADC/PWM 回调 | 上游是其他电机/硬件示例，不能直接使用 | 保留 |
| 无绝对编码器的 SMO 初始化 | 本板编码器回调为 0，原版初始化会据此判断方向并交换相序 | 保留，但特殊分支只作用于已验证的 SMO 模式 |
| 固定 `Real_offset=-2π/(3*poles)` | SMO 的 IF/观测角度路径不读取它，属于早期 HFI 调试遗留 | 删除 |
| SMO 有限边界层 | 换回硬 `sign()` 后，当前量化模型的 500/800 rpm 都无法完成接管 | 保留；结论限于当前模型、采样与参数，不称为通用上游错误 |
| SVPWM 输入乘 `sqrt(3)` | 360 角度/全部扇区电压重建测试通过；撤销后模型 800 rpm 超过电流判据 | 保留，用于匹配本移植的物理电压量纲 |
| 反电动势相角检测、方向处理、PLL 2 kHz 更新 | 撤销为原版检测器及 20 kHz PLL 后，正转通过但反转失败 | 保留当前组合；不能由此断言每个常数或降频本身都是唯一方案 |
| IF 对齐/锁定/融合及配套状态字段 | 与当前闭环标志、改速接口、积分交接、反转处理耦合 | 本轮保留，不能当作只有几行硬件适配；若继续缩减应整组对照测试 |
| 漏桶锁定计时 | 理想模型换回连续计时也通过；此前实板曾出现锁定计时被短暂波动清零 | 属于抗抖策略而非接入必需，暂保留，不能宣称已证明原始超时根因 |
| 6 V/母线比例电压限幅 | 去掉后空载模型仍通过，但没有带载/堵转/温升实板证据 | 属于试验边界，不是正常空载转动必需；暂不扩大输出范围 |
| 无限 IF 重试、闭环失锁直接退回冻结的 IF 角度 | 堵转模型持续 IF，不能按测试要求拒绝启动；退回角度也未经连续性验证 | 删除无限重试和自动回退，恢复项目原先的有界故障路径 |
| 启动状态清零 | 上一次 IF 阶段、计时及估计器状态不能带进新一轮启动 | 保留 |
| 常量函数表分派、配置范围检查 | GCC 可折叠固定模式，功能等价但不是控制功能必需 | 保留，避免重新引入无谓开销 |
| eMATH、math 的 `.fast` 标记 | 平台性能优化，不是算法功能必需 | 后续已恢复上游 math；控制入口 ITCM 保留，数学源码不再有平台改动 |
| 数学耗时计数 | 诊断，不是转动必需 | 从库中移除，仅保留板级状态兼容字段，eMATH 计数为 0 |
| `Value_normalize` 非有限输入检查 | 防止 Inf 在反复减 2π 的循环中卡死 | 为严格使用原版 math 一并撤回；原版的非有限输入风险不在本轮解决 |
| 核心文件 `<math.h>` | 原先未使用时删除；恢复原版 math 后相位检测直接调用标准库 `atan2f()` | 现在因实际使用而包含 |

恢复的有界故障路径属于项目策略，不是宣称上游自带这些保护：

- IF 对齐之后最多等待 10 s 接管，否则 `MOTOR_STATUS_SENSOR_ERROR`。
- 融合失锁持续 0.2 s 或闭环失锁持续 0.1 s，报同一错误。
- 主仓库适配层继续将库错误桥接到硬件关断；本轮不改该关断路径。

## 对照试验

`tests/sguan_change_review.py` 只在临时目录复制源码、逐项撤销改动并编译主机模型，
不修改子仓库，不访问实板。模型包含 ADC 量化，但不覆盖真实开关噪声、死区、
电源回馈、实时中断延迟等因素。

| 隔离变体 | +500/+800 rpm | -500/-800 rpm | 说明 |
| --- | --- | --- | --- |
| 当前组合 | 均通过 | 均通过 | 同时验证正反转堵转在启动期限内报错 |
| 硬 sign SMO | 均未完成接管 | 未用作本轮判据 | 不等于电机完全不转，仍可能处于 IF |
| 原版 PLL 检测器、原版更新周期 | 均通过 | 均失败 | 不能只根据正转结论撤掉方向相关修正 |
| 原版 IF＋PLL 组合 | 物理速度通过 | 均失败 | 原版无本项目的阶段/闭环标志，此项仅用独立模型速度判断，不算现有命令接口兼容通过 |
| 去掉电压限幅 | 均通过 | 未用作本轮判据 | 仅说明该空载轨迹不需要触发限幅 |
| 去掉 SVPWM 缩放 | 500 通过，800 超电流 | 未用作本轮判据 | 保留量纲匹配并补上独立扇区测试 |
| 锁定计时改为失锁即清零 | 均通过 | 未用作本轮判据 | 理想模型不能证明实板抗抖不需要 |
| 去掉 IF 启动期限 | 不作为判据 | 不作为判据 | 正反转堵转均不能按期拒绝，属于预期失败对照 |

复现：

```bash
python3 tests/sguan_integration_regression.py
python3 tests/sguan_change_review.py
./scripts/build.sh
python3 tests/startup_regression.py
```

本轮只做源代码审查、编译与主机试验，不烧写、不启动电机，也不宣称新基点和故障策略
已经通过实板验收。父仓库中另有进行中的通信/分核修改，本轮不覆盖这些工作。

## 后续：直接使用上游 math 的试验

之后用户明确要求试用原版 math，已将 `Sguan_math.c/.h` 恢复为 `5680b9e` 中的原文件，
测试校验两者逐字节相同。仅把现有 FOC 中的两处 `Value_atan2f()` 接到标准库 `atan2f()`，
没有改变相位检测公式、IF/SMO 状态机、参数、ADC 或 PWM 配置。
未引入可选后端设计，未继续保留 eMATH 数学实现。状态明确显示 `math=upstream`，
eMATH 计数 0 表示未使用，测试脚本不再要求未使用的硬件后端必须有调用次数；
电流、ADC overflow、ISR、闭环和速度误差判据均未放宽。

主机正反转 500/800 rpm、正反转堵转、SVPWM 扇区测试，以及原有隔离撤销试验均通过。
J-Link 两个 Bank 校验通过；在确认停机后下载，并做两轮复位后的实板试验：

| 序列 | 首次观测到闭环 | ISR 观测峰值 | 相电流峰值 | 稳定段估计速度最大误差 |
| --- | --- | --- | --- | --- |
| 800→700→800 rpm | 约 7.95 s | 37.05 µs | 1.410 A | 5 / 7 / 4 rpm |
| 500→600→500 rpm | 约 7.42 s | 36.83 µs | 1.437 A | 15 / 20 / 17 rpm |

两轮 ADC overflow 均为 0→0、`transitions=1`，强拖角度在接管后保持冻结，
最后均确认 `idle / fault=none / loop=stopped`。全部速度为 SMO 估算值，没有独立轴速基准。
每轮约 21 s；未测热重启、反转实板、带载、温升或长期可靠性，也不据此给出严格 WCET 保证。

复现这两轮原版 math 实板试验（确保电机环境安全、每轮开始前确认停机）：

```bash
JLINK_SN=4294967295 ./scripts/jlink_flash.sh
python3 scripts/sensorless_test.py /dev/serial/by-id/usb-SEGGER_J-Link_004294967295-if00 \
  --start-rpm 800 --next-rpm 700 --hold-seconds 4
```

低速轮次重新复位、确认校准后，使用 `--start-rpm 500 --next-rpm 600 --hold-seconds 4`。
结论限于当前单电机短时试验：原版 math 可以完成这些测试，不需要为了基本转动强制改成 eMATH。
