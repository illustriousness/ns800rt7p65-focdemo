# NS800 单电机 SguanFOC 适配

运行状态已精简为 6 个字段、24 字节，已删除只供旧日志使用的持久统计。
字段、核内必要状态与兼容性说明见[FOC 最小状态清单](../../docs/FOC_STATUS.md)。

## 来源与边界

- 上游子模块：`libraries/SguanFOC_Library`。
- URL：<https://github.com/Sguan-ZhouQing/SguanFOC_Library>。
- 上游基点：`5680b9ebce89203df0790c5e2313e7fd812513e9`，本地开发分支为 `ns800`。
- 基于该提交中的 **v3.1.0 浮点无感库**直接修改，不是 v4，也不随 `main` 自动升级。
- 上游采用 MIT 许可证，见子模块根目录 `LICENSE`。

**直接修改并编译子模块源码，不再维护外置补丁或构建源码副本。**

| 路径 | 职责 |
| --- | --- |
| 子模块 v3.1.0 目录中的 `Sguan*.c/.h` | 复用原版 IF/电流环/PLL、math；`SguanFOC.c` 有少量适配，`Sguan_SMO.c` 修正注入反馈路径 |
| 子模块 v3.1.0 目录中的 `UserData_*.h` | 上游预留的配置/回调接口：20 kHz、ATK 电机参数、PI/PLL 参数和硬件访问 |
| `ns800_foc_port.c` | ADC/PWM/CTRL_SD、RT-Thread 调度、命令、状态和硬件关断 |
| `foc_sensorless.h` | 板级只读监督：状态确认、启动期限及失跟踪关断，不生成角度或电流给定 |
| `SConscript` | 直接编译子模块，仅将目标文件放到 `build/sguan/` |
| `upstream.json` | 上游 URL、开发基点和源目录，用于来源记录，不限制后续本地提交 |

当前 CPU0 控制、CPU1 通信的任务/IRQ 分配和异步命令接口见
[双核业务分工](../../docs/CORE_LAYOUT.md)。CANopen 已接入真实异步启停、改速和故障复位，
具体范围见 [CANopen 桥接说明](../../docs/CANOPEN.md)。新桥接仅完成主机回归和编译，未烧录或运行电机验证。

板级 `UserData_*.h` 已放回子模块的默认位置，主仓库适配目录不再保留第二份参数。
这避免了源码同目录 `#include "UserData_*.h"` 优先选中上游示例的问题，也无需额外的
强制包含、文件复制或参数覆盖层。硬件驱动和 RT-Thread 代码仍留在主仓库。

## 保留的库内修改

按用户要求最大程度复用上游：`SguanFOC.h`、`Sguan_SMO.h`、`Sguan_math.c/.h`
均与基点逐字节一致。原版 `Encoder_Sensorless_Tall`、`Control_VelCur_DOUBLE`、
`Control_PosVelCur_THREE`、`Transfer_Init` 和电流采样变换函数也保持原样。
除 `UserData_*` 板级配置外，`SguanFOC.c` 保留以下适配；`Sguan_SMO.c` 另有经过实板对照的直接注入反馈修正。

| 文件 | 保留原因 |
| --- | --- |
| `VBUS_MIN` | 修正上游两处与最新头文件不一致的字段名 |
| 反转 | SMO 模式下仅翻转反向相位检测误差的符号，保留原版检测器和 20 kHz PLL |
| 无编码器启动 | 仅在本板 SMO 模式跳过绝对编码器校准，避免零回调错误交换相序 |
| 电压量纲及限幅 | 仅本板 SMO 模式保留 SVPWM `sqrt(3)` 缩放和 6 V/母线比例试验限幅 |
| GCC/ITCM | 固定模式表分派及范围检查，两个高/低环入口的 `.fast` 标记 |
| SMO 直接反馈 | 积分前计算硬 sign 注入，直接反馈电流预测器；同一注入的低通结果仅作为反电动势输出，保留原参数及结构体 |

`Sguan_math.c/.h` 与基点逐字节一致，使用原版 512 点正弦表和软件平方根，不使用 eMATH。
相位检测已回到上游的反电动势 sin/cos 检测，不再使用项目后来新增的 `atan2f()` 方案，
也没有 2 kHz PLL 降频、SMO 边界层、新的融合控制或后端框架。
正常状态接口现为 `status_schema=2`，不再保留旧数学统计字段。

## 板级监督，不替换上游控制

每 20 次高环执行一次上游低环和板级监督（1 kHz）。`observer` 直接对应上游
`Speed_abs > Sensorless_AbsMin` 的分支；连续 50 ms 检测到反电动势存在且滤波速度
与库参考速度同向、误差小于 20%，才发布板级 `closed` 并允许改速。
10 s 未确认则关断；确认后反电动势/速度跟踪异常持续 100 ms 则关断。
这不会改变上游的切换时刻，也不构成独立的转子锁定测量，更不能替代硬件保护。

启动状态清零在板级适配执行，不给上游结构体新增字段，不改上游 IF 控制器。
`Sensorless_Flag` 不被适配层伪造。原库 `Low_angle` 接管后仍按原逻辑更新；
历史日志中的 `forced_mrad` 仅为 IF 诊断快照，`pll_error_mV` 是电压量纲；
当前精简接口不再发布这些诊断字段，不能用它们声称有独立角度测量。
SMO 原始 `h=6`、`Wc=800`、PI/PLL 等参数未重调，仅删除已不存在的 `Boundary` 配置。
NLFO 的原版分支已恢复；本板运行仍限定 SMO 模式 8，未验证其他模式实板表现。

当前控制包络集中定义在 `foc_limits.h`：启动 ±350～800 rpm，闭环同向改速到
±2500 rpm；运行中相电流 3.0 A、母线 22～27 V、估算超速 2750 rpm 会触发关断。
2500 rpm 新范围只做主机回归，未做全范围实板验收。控制权默认在 CANopen；
`motor owner uart` / `motor owner can` 用于交接，交接先 STOP 并等待 `stop_seq`，
切换期间两个来源都不能提交新命令。

## 构建和检查

```bash
git submodule update --init --recursive
./scripts/build.sh
python3 tests/sguan_integration_regression.py
python3 tests/sguan_change_review.py
python3 tests/sguan_smo_feedback_regression.py
python3 tests/sguan_arm_compile.py
git -C libraries/SguanFOC_Library diff --stat
```

不再需要 GNU `patch` 或源码生成器。SCons 使用 `VariantDir(..., duplicate=0)`，
从子模块直接编译；`build/sguan/` 仅存放目标文件，不应存在 `.c/.h` 副本。
主机测试也直接编译相同的子模块源码，不要求子模块工作区干净，也不修改其源码。

主机测试覆盖正反转 500/800 rpm 和四个初始角度、稳态物理/估算速度误差、
正反转堵转期限及 SVPWM 全扇区归一化。审查脚本严格限定 SMO 的反馈修正增量、校验其他原版文件/函数，
板级监督不写控制数据，并编译库的 SMO/NLFO 两种配置。
这不能替代实板、负载、堵转或长期运行验收。实板上电默认停机，迁移不修改命令和调参。

用户确认 CANopen 台架工作完成后，已重新启用顶层 `sguan` 构建，并用含 FOC 的完整镜像
完成启动布局检查和两轮实板回归。当时 CANopen 仍为 `controls=DISCONNECTED`，
这些历史串口电机结果不能当作当前真实 CANopen 桥接的实板验证。
`sguan_arm_compile.py` 仍可用于独立 ARM 编译和可重定位链接，不生成可下载电机镜像。

未提交的子模块修改仅存在本地，父仓库的 gitlink 不会保存这些修改。分享或归档时，
需要先在子仓库提交并推送到自己的 fork，再更新 `.gitmodules` 的 URL 和父仓库 gitlink。
不向作者上游推送。合并上游更新时单独评审，不要直接用 `git submodule update --remote`
将未知的新算法带入已验证基线。

## 后续原版 math 实板试验

以下是最大复用收敛之前的历史结果，当时仍使用自写 IF 接管和边界层 SMO，
不能作为当前原版 IF/PLL/SMO 组合的实板验收。

按用户要求只恢复上游 math，并在最新完整固件上复位后测试：

| 测试 | 接管观测时刻 | ISR 观测峰值 | 相电流峰值 | ADC overflow |
| --- | --- | --- | --- | --- |
| 800→700→800 rpm | 约 7.95 s | 37.05 µs | 1.410 A | 0→0 |
| 500→600→500 rpm | 约 7.42 s | 36.83 µs | 1.437 A | 0→0 |

两轮均通过现有脚本的闭环、改速、速度误差、电流、50 µs 周期及停机判据，停机确认为
`idle / fault=none / loop=stopped`。每轮为复位后的启动，不覆盖热重启。
速度为 SMO 估算值，非独立测速；这是两轮约 21 s 的短时空载试验，不是严格 WCET 或可靠性验收。

## SMO 直接反馈修正及实板效果（2026-10-30）

用户确认 diff 后，仅修改 `Sguan_SMO.c` 的反馈路径及注入计算时序，不加入边界层，
不改 PLL、电机、h/Wc、IF、ADC/PWM 或六字段状态接口。诊断仅存在隔离构建中。

500 rpm 原版→修正版→原版→修正版的原始 PLL 标准差为约 822→143→777→148 rpm；
800 rpm 原版/修正版为约 744/146 rpm。控制角高频输出纹波也明显降低，
但滤波速度和 Iq 波动没有一致改善，不声称已修复全部速度波动或提高真实轴角精度。
修正版 500→600→500 rpm、每段 8 s 的改速测试通过；修正版测试电流采样峰值
不超过 1.346 A，ISR 观测峰值不超过 28.443 µs，ADC overflow 均为 0。
正常镜像已去掉临时诊断并保持停机，状态接口仍为 24 字节。

完整原始波形、参数一致性、固件校验值及限制见
[直接反馈实板证据](../../docs/bringup_evidence/sguan_smo_direct_feedback_20261030/README.md)。
